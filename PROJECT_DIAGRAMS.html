erDiagram
    users ||--o{ events : "organizes"

    users ||--o{ comments : "writes"
    users ||--o{ feedback : "gives"
    users ||--o{ remember_tokens : "has"
    events ||--o{ rsvps : "receives"

        INT id PK
        VARCHAR name
        VARCHAR email UK
        VARCHAR password_hash
        ENUM role
        DATETIME created_at
    }
    events {
        INT id PK
        INT organizer_id FK
        VARCHAR title
        TEXT description
        VARCHAR image_path
        VARCHAR location
        VARCHAR category
        DATETIME event_date
        DATETIME event_end
        INT capacity
        TINYINT is_verified
        DATETIME created_at
    }
    rsvps {
        INT id PK
        INT event_id FK
        INT user_id FK
        ENUM status
        DATETIME approved_at
        INT approved_by FK
        DATETIME created_at
    }
    comments {
        INT id PK
        INT event_id FK
        INT user_id FK
        TEXT body
        INT parent_comment_id FK
        DATETIME created_at
    }
    feedback {
        INT id PK
        INT event_id FK
        INT user_id FK
        TINYINT rating
        TEXT comment
        DATETIME created_at
    }
    remember_tokens {
        INT id PK
        INT user_id FK
        VARCHAR selector UK
        CHAR validator_hash
        DATETIME expires_at
    }

8. Remember-Me Split Token Flow

sequenceDiagram
    participant B as Browser
    participant S as Server
    participant DB as MySQL
    Note over B,DB: Token Issuance
    S->>S: selector = random_bytes 8 hex
    S->>S: validator = random_bytes 32 hex
    S->>S: validatorHash = sha256 validator
    S->>DB: INSERT remember_tokens
    S->>B: Set-Cookie remember_me=selector:validator
    Note over B,DB: Auto-Login on Next Visit
    B->>S: Request with remember_me cookie
    S->>S: Split cookie into selector + validator
    S->>DB: SELECT FROM remember_tokens WHERE selector = ?
    DB-->>S: Token row with validator_hash
    S->>S: hash_equals sha256 validator vs stored_hash
    S->>S: Check expiry
    S->>DB: DELETE old token - rotation
    S->>S: Issue NEW token
    S->>S: login_user with fetched user
    S->>B: Set-Cookie with new token
